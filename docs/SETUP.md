# Zagot+ Developer Setup Guide

Complete guide to set up the development environment for Zagot+.

## Prerequisites

- Android Studio Hedgehog (2023.1.1) or newer
- JDK 17
- Git
- Supabase account (free tier works)

## Quick Start

### 1. Clone and Open Project

```bash
git clone <repository-url>
cd zagotPlus
```

Open `android/` folder in Android Studio.

### 2. Setup Supabase Backend

See [supabase/README.md](../supabase/README.md) for detailed Supabase configuration.

**Summary:**
1. Create a Supabase project at [supabase.com](https://supabase.com)
2. Run all migrations from `supabase/migrations/` in order
3. Copy your Project URL and Anon Key

### 3. Configure Local Properties

Create/edit `android/local.properties`:

```properties
# SDK path (auto-generated by Android Studio)
sdk.dir=/path/to/Android/Sdk

# Supabase configuration (required)
supabase.url=https://your-project.supabase.co
supabase.anon.key=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

**⚠️ Security Warning**: Never commit `local.properties` to version control!

### 4. Build and Run

```bash
cd android
./gradlew assembleDebug
```

Or use Android Studio's Run button.

## Database Schema

The app uses Room for local storage and syncs with Supabase PostgreSQL.

### Entities

| Table | Purpose |
|-------|---------|
| `locations` | Physical locations (kiosk, mobile) |
| `products` | Product catalog with pricing |
| `transactions` | Immutable ledger of all operations |
| `purchase_batches` | Groups purchase transactions by session |
| `sale_batches` | Groups sale transactions by session |
| `expense_categories` | Categories for cash expenses |
| `cash_operations` | Manual cash deposits/withdrawals |

### Migrations

Room migrations are in `ZagotDatabase.kt`. Supabase migrations are in `supabase/migrations/`.

**Important**: Both must be kept in sync!

## Sync System

### How It Works

1. **Local First**: All operations write to Room immediately
2. **Background Sync**: WorkManager schedules sync every 15 minutes
3. **Manual Sync**: User can trigger sync (rate-limited to 30s)
4. **Conflict Resolution**: `local_id` UUID ensures idempotent upserts

### Sync Order (Important!)

Push order respects foreign key dependencies:
1. Products
2. Expense Categories
3. Purchase Batches
4. Sale Batches
5. Transactions
6. Cash Operations

## Security Features

- **Encrypted Preferences**: Device ID and location stored with EncryptedSharedPreferences
- **PIN Authentication**: PBKDF2-HMAC-SHA256 with 10,000 iterations
- **Session Timeout**: 4-hour session expiry
- **Lockout Protection**: 30-second lockout after 3 failed attempts

## Configuration Constants

See `Config.kt` for centralized settings:
- `PAGE_SIZE`: 50 items
- `SYNC_INTERVAL_MIN`: 15 minutes
- `MIN_SYNC_INTERVAL_MS`: 30 seconds
- `SESSION_TIMEOUT_MS`: 4 hours

## Common Issues

### Build Fails with "Supabase key not found"
Check `local.properties` has `supabase.url` and `supabase.anon.key`

### "Security initialization failed" at startup
EncryptedSharedPreferences failed. Check device Keystore health.

### Sync fails with "column not found"
Supabase schema out of sync. Apply all migrations.

### Room migration failed
Add migration in `ZagotDatabase.kt`. See existing `MIGRATION_*` examples.

Connection via USR-W610 WiFi adapter:
- Protocol: TCP/IP
- Port: 8899 (configurable)
- Data format: ASCII, CR/LF terminated
- Commands:
  - `W?` - Request current weight
  - Response: `ST,GS,+  12.345 kg` or `ST,US,+   0.000 kg` (unstable)

Connection via Bluetooth SPP:
- Protocol: ESC/POS
- Paper width: 58mm
- Commands: Standard Epson ESC/POS
